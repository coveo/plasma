# Breadcrumbs

Navigation trail that shows a page's ancestors within a hierarchy.

## Overview

The `Breadcrumbs` helps users understand their location and return directly to an ancestor page.

## Guidelines

### When to use

- The page sits two or more levels deep in a navigation hierarchy.
- Users may need to return directly to an ancestor page.
- A drill-down workflow moves from a list to item details.

### When not to use

- For a flat application without a meaningful hierarchy.
- Inside a modal or drawer that users should close instead of navigating away.
- When the page header already provides breadcrumbs.

### Best practices

- Use `Header.Breadcrumbs` inside a page header and standalone `Breadcrumbs` elsewhere.
- With one ancestor, show a single breadcrumb with a back arrow. In a page header, set `single` on
  `Header.BreadcrumbAnchor`; the arrow isn't added automatically.
- Show no more than three ancestor links.
- Don't include tabs in breadcrumbs, since tabs aren't pages. Link to the page that contains the tabs instead.
- Return users to the tab the item belongs to, however they reached it. For example, on a ranking rule, the breadcrumb
  reads **< Product listing** and opens Product listing on the Ranking rules tab. If the item doesn't belong to a
  specific tab, open the parent page's default tab.
- Link every item to a fixed parent page, never to the browser's previous page.
- Omit the current page because the page header already identifies it.
- Use `Anchor` with `inherit` for every item, and let the component add separators.
- Make every item a link; don't use `Header.BreadcrumbText`.

### Content guidelines

- Use the parent page's name as the link text, such as **Sources** or **Product listing**.
- Don't use generic labels such as **Back**, **Go back**, or **Previous**.
- Don't add the tab name to the link text, as in **Product listing - Ranking rules**.
