# PasswordInput

Password field that masks sensitive values and lets users reveal them temporarily.

## Overview

`PasswordInput` protects passwords, tokens, and other secret values from casual viewing during entry.

It keeps the value masked by default while providing a built-in reveal action for verification.

## Guidelines

### When to use

- Users enter a password, secret, token, or similar sensitive value.
- The value should be masked by default but available for temporary verification.
- A secret must remain in a field layout while edits are unavailable.

### When not to use

- Use `TextInput` for values that are not sensitive.
- Avoid masking values users need to scan or compare frequently.
- Pair a read-only input with `CopyToClipboard` when users primarily need to copy a generated secret.

### Best practices

- Provide a visible label that identifies the expected secret.
- Use `readOnly` when users can review the value but cannot edit it.
- Use `disabled` only when the field is unavailable.
- Keep requirements visible instead of relying on placeholder text.

### Content guidelines

- Name the specific secret in the label, such as **Database password**.
- State format or rotation requirements in the description.
- Explain how to fix the value in validation messages.
