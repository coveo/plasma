# Header

Page-level title area with optional breadcrumbs, description, documentation link, and actions.

The `Header` establishes the purpose and hierarchy of a page or major section. It gives related context and page-level actions a consistent location around the title.

## Demo

<Canvas of={HeaderStories.Demo} />

## Usage

### When to use

- A page or major section needs a clear title and supporting context.
- Breadcrumbs or external documentation help users understand the view.
- Actions apply to the page or section as a whole.

### When not to use

- A card or small form group only needs a local heading.
- The surrounding page already provides its title structure.
- Actions belong near a form, in a modal footer, or in a sticky footer.

### Best practices

- Use the primary variant for page headers and the secondary variant for lower-level sections.
- Place only page-level actions in `Header.Right` and limit competing choices.
- Use breadcrumbs to show hierarchy, with a link for each ancestor page. Leave the current page out of the trail; the
  header title already shows it.
- With one ancestor, set `single` on `Header.BreadcrumbAnchor` to show the back arrow; it isn't added automatically.
- Make every breadcrumb item a `Header.BreadcrumbAnchor`; `Header.BreadcrumbText` is deprecated.
- Link to relevant external help through `Header.DocAnchor`.

## Content and copy

- Write specific, scannable titles.
- Use the description to explain the page purpose rather than repeat the title.
- Keep breadcrumb labels aligned with the application's hierarchy.
