## How to apply it

Through props first.
Fall back to the CSS variable only when a prop cannot express what you need, such as inside a style object.

```tsx
<Text c="blue.6">Indexed shade</Text>
<Badge color="red">Palette name</Badge>
<Box style={{borderColor: 'var(--mantine-color-gray-3)'}} />
```

<Unstyled>
    <Rule>Never hardcode a hex. A hardcoded colour stops following the theme the day the theme changes.</Rule>
</Unstyled>

## Primary

The primary palette is **blue** and the primary shade is **5** — but both are theme configuration, not constants.

<Unstyled>
    <Rule>
        Reference <code>primary</code>, never <code>blue</code>. Use{' '}
        <code>var(--mantine-primary-color-{'{0..9}'})</code> or the colour name <code>primary</code>.
    </Rule>
    <Caption>
        Writing <code>blue</code> where you mean "the primary action colour" makes the component stop following the
        theme the day primary changes. The two are the same value today and that is exactly what makes the mistake
        invisible.
    </Caption>
</Unstyled>

## Text on an arbitrary background

When the background is chosen at runtime — a tag colour, a chart series, a user-picked value — do not guess the foreground.

```tsx
import {getContrastColor} from '@coveord/plasma-mantine';

const fg = getContrastColor({color, theme, autoContrast: true});
```
