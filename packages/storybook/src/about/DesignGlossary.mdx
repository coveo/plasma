# Glossary

Definitions for terms commonly used in the Plasma Design System.

## A

**Accessibility expectations**: Baseline requirements for contrast, focus, keyboard interaction, and other accessibility considerations.

**Anti-pattern**: An example of how a component or pattern should not be used.

## C

**Component**: A reusable interface element used to build product experiences.

**Consistency**: The use of shared foundations to create a unified experience across interfaces.

**Contextual mapping**: The connection between a semantic token and the specific context where it is used.

**Core component**: A general-purpose, product-agnostic building block.
Examples include Button, Input, Dropdown, Checkbox, Modal, and Tabs.
If a component assumes Coveo data or a Coveo-specific concept, it is not a core component.

## D

**Design system**: The collection of foundations, components, patterns, and experiences used to build consistent products.

**Design token**: A named design value used across design and code.
Examples include color, typography, spacing, radius, elevation, and motion values.

## E

**Experience pattern**: A repeatable sequence of steps that helps a user complete a larger goal.
An experience pattern can span multiple pages, states, and decisions.
Examples include creating a source, configuring a source, and multi-step setup.

## F

**Figma library**: The shared Figma resource containing Plasma variables, components, and other design assets.

**Flexibility**: The ability for the system to evolve in a controlled way without breaking existing implementations.

**Foundation**: A fundamental rule, value, or asset on which components and patterns are built.
Foundations include color, typography, spacing, radius, elevation, motion, breakpoints, and accessibility expectations.

## I

**Interaction pattern**: A repeatable solution to a localized interface problem.
Interaction patterns combine components with behavior, content, and product logic.
Examples include destructive-action confirmation, empty states, table filtering, and inline validation.

## L

**Library origin**: The library from which a component originates.
In Plasma, a component may originate from Mantine or be Plasma-specific.

## M

**Mantine**: The component library on which most Plasma components are based.

**Motion**: The foundational rules governing animation and movement in an interface.

## P

**Page pattern**: A reusable page-level structure and information architecture.
Examples include overview pages, detail pages, settings pages, dashboards, and form pages.

**Plasma**: Coveo’s design system.

**Plasma-specific component**: A component created for Plasma rather than inherited from the Mantine library.

**Primitive**: A raw, foundational design value from which other tokens and system decisions are created.

**Product component**: A reusable, product-specific solution built on top of core components.
Product components understand Coveo concepts or data.
Examples include a project selector connected to Coveo data, a privileges table, or a source configuration module.

## S

**Scalability**: The ability of the system to support multiple products, themes, and future extensions.

**Semantic token**: A token named according to its purpose rather than its raw value.

**Single source of truth**: The centralized, authoritative location for a design system value, rule, or artifact.

**Storybook**: The site used to document and organize Plasma components and patterns.

## T

**Template**: A reusable page structure used as the basis for a page pattern.

**Token**: Also called a _design token_.
See [words starting with D](#D).

**Typography**: The foundational rules governing font families, scales, weights, readability, and hierarchy.

## V

**Visual foundations**: Foundational visual properties such as border radius, shadows, opacity, and motion.
