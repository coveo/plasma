## Summary

Users need to move to another page, section, or resource, such as the documentation site, without losing track of
where they are or whether they're leaving the product. Links handle navigation only; they never perform an action.

## When to use

- Moving users to another page, section, or external resource, such as another Coveo app or the documentation site.
- Showing a URL.

## When not to use

- For any action, use a `Button`.
- To show the user's location in a hierarchy, use `Breadcrumbs`.
- To send users into another app where they would land with no context, such as an empty list or the first step of a
  creation flow, link to the feature's documentation instead.

## How it works

1. **Link text** describes the destination.
2. **External icon (↗)** trails the text, on external links only. A link is external when its destination is outside
   the Coveo apps, such as the documentation site; links to another Coveo app aren't external. Icon-only links with
   this icon, such as `Header.DocAnchor`, are styled as action icons and follow their own component guidance.
3. **Target**: destinations in the product open in the same tab; external destinations open in a new tab.
   Links to another Coveo app may open in either, depending on the user's task.

Activating a link navigates to its destination. The pattern has no loading, error, or disabled state. Because external
links open in a new tab, the current page stays where the user left it.

## Rules

- **MUST** use a `Button`, not a link, for any action.
- **MUST** open external links in a new tab.
- **MUST** include a trailing ↗ icon on standalone external links. Inline links never include it.
- **MUST NOT** include the ↗ icon on links to another Coveo app.
- **MUST NOT** add any other icon to a link.
- **SHOULD** link to the feature's documentation instead of sending users to an empty state or the first step of a
  creation flow in another app.

## Content

- Make link text describe what users will find at the destination.
- Make inline links read naturally within the sentence.
- Don't use **Read more** when the label is already descriptive. Use labels like **View ranking documentation**,
  **View operator definitions**, or **Read implementation guidelines**.
- Keep standalone link text short; don't use a full sentence as link text.

## Accessibility

- Link text must make sense out of context, since screen reader users often browse a list of links.
- The ↗ icon is decorative and hidden from screen readers. Tell screen reader users that the link opens in a new tab, for example with visually hidden text such as
  "(opens in a new tab)".
- Links are activated with Enter, not Space. Using a link for an action breaks keyboard users' expectations.
