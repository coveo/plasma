A component answers "what do I use?".
A pattern answers "how do these go together, and what is the right behaviour once they do?".

Patterns show how Plasma components work together to complete a task — filtering a list, handling an empty state,
navigating with links. Use them to keep similar experiences consistent across the product, so a user who learns one
screen can predict the next.

## The three layers

Patterns come in three kinds, and the kind decides how much a pattern settles — and how big a decision it is to
change one. [How it works](./?path=/docs/overview-how-it-works--docs) defines them in full, next to the equivalent
taxonomies for components and tokens. What the layer changes in practice:

## When to write one

A pattern earns a page when the same combination of components has been assembled more than once, and the teams
assembling it made different calls.

That is the signal: not that something is common, but that something common is being done inconsistently.
If there is only one way it is being built, the component pages already say enough.
