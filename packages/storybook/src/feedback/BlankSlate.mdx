# BlankSlate

Empty state container for views with no content to display.

## Overview

Use a BlankSlate to fill a view when there's nothing to show yet, for example, an empty table, a filtered result set with no matches, or a section that hasn't been configured.

It provides a consistent, bordered container for an empty-state message and optional actions.

## When to use

The most common use case is a table empty state, paired with a way to recover, like clearing filters.

```tsx
import {BlankSlate, Button, Table, Title} from '@coveord/plasma-mantine';

const NoData = ({clearFilters}: {clearFilters: () => void}) => (
    <BlankSlate>
        <Title order={4}>No data found for those filters</Title>
        <Button.Tertiary onClick={clearFilters}>Clear filters</Button.Tertiary>
    </BlankSlate>
);

const Example = () => (
    <Table.NoData>
        <NoData clearFilters={() => {}} />
    </Table.NoData>
);
```

You can also use it for simpler empty states with no action.

```tsx
import {BlankSlate, Title} from '@coveord/plasma-mantine';

const EmptyState = () => (
    <BlankSlate>
        <Title order={4}>No data</Title>
    </BlankSlate>
);
```

If the surrounding layout already has its own border, turn off the BlankSlate border to avoid doubling up.

```tsx
import {BlankSlate, Title} from '@coveord/plasma-mantine';

const EmptyState = () => (
    <BlankSlate withBorder={false}>
        <Title order={4}>Empty state</Title>
        This view has no content yet.
    </BlankSlate>
);
```

## Content guidance

**Heading (`Title`):**

- Lead with what's missing or why the view is empty: "No data found for those filters" not "Empty"
- Use sentence case
- Keep it to one short phrase. Don't write a full sentence with a period

**Body or description (`children`):**

- Add a short explanation only when the reason for the empty state isn't obvious from the heading
- Don't repeat the heading in different words
- Keep it to one sentence

**Action label (`Button`):**

- Use a verb that describes exactly what happens: "Clear filters" not "Try again"
- Keep it to 3 words or fewer
- Only include an action when there's a clear recovery path
