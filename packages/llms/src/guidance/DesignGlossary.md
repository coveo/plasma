# Design Glossary

- Accessibility expectations — Baseline requirements for contrast, focus, keyboard interaction, and related concerns
- Anti-pattern — How a component or pattern should NOT be used
- Component — A reusable interface element used to build product experiences
- Consistency — Use of shared foundations to create a unified experience across interfaces
- Content guidelines — Rules established for content to keep the UX clear, consistent, and on brand
- Contextual mapping — The connection between a semantic token and the specific context where it applies
- Core component — A general-purpose, product-agnostic building block (e.g., Button, Input, Dropdown, Checkbox, Modal, Tabs). If it assumes Coveo data or a Coveo-specific concept, it is NOT a core component.
- Design system — The collection of foundations, components, patterns, and experiences used to build consistent products
- Design token — A named design value used across design and code (color, typography, spacing, radius, elevation, motion)
- Experience pattern — A repeatable multi-page sequence helping a user complete a larger goal (e.g., creating a source, configuring a source, multi-step setup)
- Figma library — The shared Figma resource containing Plasma variables, components, and design assets
- Flexibility — The system's ability to evolve without breaking existing implementations
- Foundation — A fundamental rule, value, or asset on which components and patterns are built (color, typography, spacing, radius, elevation, motion, breakpoints, accessibility expectations)
- Interaction pattern — A repeatable solution to a localized interface problem combining components with behavior, content, and product logic (e.g., destructive-action confirmation, empty states, table filtering, inline validation)
- Library origin — Whether a component comes from Mantine or is Plasma-specific
- Long-form copy — Extended text providing context, detail, or instruction across several paragraphs. Does not appear in the Administration Console; typical for product documentation and Level Up+ content.
- Mantine — The component library on which most Plasma components are based
- Microcopy — Short, functional text that guides users at decision points: tooltips, placeholder text, error messages, helper text
- Motion — Foundational rules governing animation and movement
- Page pattern — A reusable page-level structure and information architecture (e.g., overview pages, detail pages, settings pages, dashboards, form pages)
- Plasma — Coveo's design system
- Plasma-specific component — A component created for Plasma, not inherited from Mantine
- Primitive — A raw foundational design value from which other tokens and system decisions are derived
- Product component — A reusable, product-specific solution built on core components that understands Coveo concepts or data (e.g., project selector, privileges table, source configuration module)
- Scalability — The system's ability to support multiple products, themes, and future extensions
- Semantic token — A token named by purpose rather than raw value
- Short-form copy — Brief, scannable text communicating a single idea (page titles, descriptive text, confirmation text, banner text). Can range from a few words to a couple of paragraphs.
- Single source of truth — The centralized authoritative location for a design system value, rule, or artifact
- Storybook — The documentation site for Plasma components and patterns (https://plasma.coveo.com/)
- Template — A reusable page structure used as the basis for a page pattern
- Token — Synonym for design token
- Typography — Foundational rules for font families, scales, weights, readability, and hierarchy
- UI copy — Text rendered as part of a UI component: button labels, menu items, field labels, status messages
- UX copy — Also called UX writing. The language within an interface that guides users throughout their experience.
- Visual foundations — Foundational visual properties: border radius, shadows, opacity, motion
